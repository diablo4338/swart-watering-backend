# Smart Watering MCU API Contract

This document describes the HTTP contract between the Python control plane and
ESP32-C3 smart-watering controllers.

OpenAPI schema: `firmware/mcu_api.openapi.yaml`

## Runtime Addressing

Each controller exposes a local HTTP API:

```text
http://<controller-ip>/
```

The backend sends operation callbacks to the URL built from
`SMART_WATERING_NODE_URL`:

```text
http://192.0.2.10:8080/operations/callback
```

`SMART_WATERING_NODE_URL` must be reachable from ESP devices over LAN. Do not use
`localhost` unless the controller runs on the same host.

The controller API has no authentication. Requests from the backend use JSON
with `Content-Type: application/json` when a request body is present.

## Device Types

Supported device types:

```text
plant
tank
```

Only `tank` devices can start watering.

## Read Endpoints

### `GET /healthz`

Returns `200 OK` when the controller is awake and its HTTP server is running.

Response body:

```text
ok
```

### `GET /metrics`

Returns text metrics:

```text
useful_weight_g 83
gross_weight_g 533
```

### `GET /constants`

Returns compile-time MCU constants and selected runtime calibration values. Wi-Fi credentials are not exposed.

Example response:

```json
{
  "pins": {
    "hx711_dout_pin": 19,
    "hx711_sck_pin": 3,
    "status_led_pin": 1,
    "start_pin": 10
  },
  "weight": {
    "default_offset_raw": 116274,
    "default_raw_per_gram": 214.0,
    "read_samples": 1,
    "read_interval_ms": 500,
    "zero_deadband_g": 3.0,
    "weight_buffer_size": 5,
    "default_tare_weight_g": 0.0,
    "tare_tolerance_g": 20.0
  },
  "runtime": {
    "zero_raw": -123456,
    "raw_per_gram": 214.5
  }
}
```

### `GET /watering`

Returns current device, watering, config and weight state.

Example response:

```json
{
  "device": {
    "type": "plant",
    "name": "plant_1"
  },
  "watering": {
    "active": false,
    "state": "waiting",
    "last_operation_type": "config",
    "last_operation_status": "completed"
  },
  "config": {
    "target_g": 0.0,
    "tare_weight_g": 450.0,
    "dry_weight_g": 120.0,
    "zero_raw": -123456,
    "raw_per_gram": 214.0,
    "sleep_disabled": true,
    "sleep_interval_min": 15
  },
  "weight": {
    "useful_weight_g": 83.0,
    "gross_weight_g": 533.0,
    "water_used_g": 0.0
  }
}
```

Known `watering.state` values:

```text
waiting
watering
```

Known operation type values:

```text
none
start
stop
config
sleep
zero
```

Known operation status values:

```text
none
in_progress
completed
stopped
failed
```

## Common Operation Fields

Write endpoints accept these fields when the caller wants operation tracking:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback"
}
```

`operation_id` is generated by the backend. `callback_url` is where the
controller posts asynchronous operation lifecycle events.

Callbacks are best-effort. A failed callback does not roll back controller state.

## Write Endpoints

### `POST /config`

Updates controller config. Fields can be sent partially, but at least one config
field must be present.

Persisted fields:

```text
device_type
name
tare_weight_g
dry_weight_g
```

Example request:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback",
  "device_type": "plant",
  "name": "plant_1",
  "tare_weight_g": 450,
  "dry_weight_g": 120
}
```

Success response:

```json
{"status":"config_updated"}
```

Possible errors:

```json
{"error":"read_failed"}
{"error":"invalid_device_type"}
{"error":"invalid_name"}
{"error":"invalid_tare_weight_g"}
{"error":"invalid_dry_weight_g"}
{"error":"empty_config"}
{"error":"config_update_failed"}
```

### `POST /watering/start`

Starts watering. Only valid for `tank` devices.

`target_g` is the target poured mass in grams.

Example request:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback",
  "target_g": 120
}
```

Success response:

```json
{"status":"accepted"}
```

Possible errors:

```json
{"error":"read_failed"}
{"error":"invalid_target_g"}
{"error":"watering_already_active"}
{"error":"device_not_tank"}
{"error":"watering_start_failed"}
{"error":"no_memory"}
{"error":"task_create_failed"}
```

### `POST /watering/stop`

Requests stop for the current watering cycle.

Example request:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback"
}
```

Success responses:

```json
{"status":"stop_requested"}
{"status":"no_active_watering"}
```

Possible error:

```json
{"error":"read_failed"}
```

### `POST /sleep/enable`

Enables deep sleep.

Example request:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback"
}
```

Success response:

```json
{"status":"sleep_enabled"}
```

Possible errors:

```json
{"error":"read_failed"}
{"error":"sleep_enable_failed"}
```

### `POST /sleep/disable`

Disables deep sleep and keeps the controller awake.

Success response:

```json
{"status":"sleep_disabled"}
```

Possible errors:

```json
{"error":"read_failed"}
{"error":"sleep_disable_failed"}
```

### `POST /sleep/interval`

Updates the deep sleep wake interval in minutes and persists it.

Valid range:

```text
1..50
```

Example request:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback",
  "minutes": 20
}
```

Success response:

```json
{"status":"sleep_interval_updated"}
```

Possible errors:

```json
{"error":"read_failed"}
{"error":"invalid_sleep_interval"}
{"error":"sleep_interval_update_failed"}
```

### `POST /zero`

Captures the latest raw HX711 sample as zero and persists it.

Example request:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback"
}
```

Success response:

```json
{"status":"zero_captured"}
```

Possible errors:

```json
{"error":"read_failed"}
{"error":"zero_capture_failed"}
```

### `POST /calibration`

Calibrates the HX711 raw-per-gram coefficient using the latest raw sample and the saved `zero_raw`, then persists it.
Place a known weight on the scale before calling this endpoint.

Example request:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "callback_url": "http://192.0.2.10:8080/operations/callback",
  "weight_g": 500
}
```

Success response:

```json
{"status":"calibrated"}
```

Possible errors:

```json
{"error":"read_failed"}
{"error":"invalid_calibration_weight_g"}
{"error":"calibration_failed"}
```

## Operation Callback

When both `operation_id` and `callback_url` are present, the controller posts:

```http
POST /operations/callback
Content-Type: application/json
```

Example callback body:

```json
{
  "operation_id": "7a5c5f9e-d909-470f-ae20-46a72b0dbf9d",
  "status": "completed",
  "detail": "target_reached"
}
```

Callback node success response:

```json
{"status":"recorded"}
```

The backend normalizes callback statuses:

```text
created                 -> queued
received, accepted,
send, sent              -> accepted
started, start          -> running
completed, complete, ok -> success
timeout                 -> timeout
failed, failure         -> error
```

Known final callback details include:

```text
target_reached
stop_requested
weight_not_changing
no_weight_available
no active watering
config_updated
sleep_enabled
sleep_disabled
sleep_interval_updated
zero_captured
```

## Backend Queue Semantics

The backend queues write operations because controllers may be asleep.

Watering start and sleep disable commands are retried until the worker max wait
timeout. Other commands and status reads are attempted once. A queued watering
stop cancels queued watering starts for the same device.

Operation statuses used by the backend:

```text
queued
sending
accepted
running
success
error
timeout
cancelled
```
